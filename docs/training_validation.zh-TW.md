# 新模型訓練：獨立校正與驗收

此功能適用於完整新模型訓練，直接整合在選片、切片審核與完成頁，不需使用舊的「模型考試」。更新後請重新啟動服務，資料庫會自動新增用途與標籤欄位。

## 操作

1. 只選取一次資料，保留預設勾選的「自動校正與驗收」。系統以 PANEL ID（介面的 Glass ID）分組，不需填批次或指定用途；手動資料夾以 panel 資料夾名稱作為 ID。
2. 審核頁沿用加入／排除操作：保留＝OK，排除＝NG，不需額外標記或確認其餘為 OK。排除的切片不加入正常 memory bank；校正組與驗收組內的排除切片會作為各組 NG。重新加入即改回 OK，以最後的加入／排除結果為準。
3. 使用歷史資料時，可選手動資料夾來源並勾選「包含下一層資料夾」。支援 `根目錄 / 日期或批次 / panel / 光源圖片`；上層日期、批次資料夾不再影響分組。
4. 有需要時展開「進階：驗收目標」，設定可接受的 OK 誤判率與 NG 漏檢率（百分比）。留白時仍有建議與實測結果，但不會標示符合目標。
5. 完成頁比較原門檻 0.35 與建議門檻，並提供各驗收 PANEL ID 表現、錯判圖片與完整 JSON 報告。
6. 點「採用建議門檻」才會更新該子模型的 YAML 與 thresholds.json，另存採用紀錄。此操作不會啟用模型；已啟用的模型需先停用才能採用。

關閉「自動校正與驗收」時，沿用原正常樣本訓練流程。局部重訓尚未提供自動分組。舊版自動分組 job 若仍在審核階段，重新載入時會保留加入／排除結果，並依 PANEL ID 及當初勾選的 INNER／EDGE 重新分配；已開始訓練或完成的歷史報告不會重分組。舊版手動指定用途的 job 維持原規則。

## 自動分組

系統依 PANEL ID 及勾選的 INNER／EDGE 分組；相同 ID 的不同光源、不同區域切片留在同一用途，不跨訓練、校正、驗收。每個區域各有至少三個不同 ID 時，優先確保該區域有訓練、校正與驗收，再朝各保留約 20% 作為校正及驗收分配；每個有資料的區域至少留一個 ID 供訓練。`corners_only` 算 EDGE，相同 ID 在不同路徑選了不同區域時，會合併考慮。

例：六片都選 INNER＋EDGE，兩邊各為訓練四片、校正一片、驗收一片。若三片只選 INNER、三片只選 EDGE，兩邊各為訓練一片、校正一片、驗收一片；此時整體是 2／2／2，不強制整體 4／1／1。同樣的 ID 與區域選擇，即使選片順序不同，結果也相同。這是 PANEL 間驗證，不代表已涵蓋不同生產批次。

審核頁會依目前光源的實際切片，分別顯示 INNER／EDGE 的訓練、校正、驗收 PANEL ID 數及 OK／NG 張數。訓練欄只計保留的 OK；校正、驗收欄同時計入保留與排除切片。全部排除某組 OK、未產生該區域切片或缺少 NG 時，會顯示具體缺項；切換光源、加入／排除後會更新。分組不依排除結果重新洗牌。

若兩個區域都不足三個 ID，全部保留給正常樣本訓練。只有其中一區足夠時，優先完成該區分組，另一區依實際缺項提示資料不足；同一 PANEL ID 仍不跨用途。ID 足夠也不保證校正與驗收各有 OK、NG；缺少任一類仍標為資料不足，不會把其他組的圖片搬過來補數。訓練組的排除切片不會移入獨立校正或驗收。

分組設定會保存在 job 與報告中。重新選圖仍需進行原本的加入／排除審核，不另加標記作業。

## 判讀

- 校正與驗收資料不加入 memory bank。校正組 OK／NG 可提供模型分數正規化及門檻選擇；驗收組不參與兩者。
- OK／NG 直接依加入／排除決策產生，NG 包含使用者排除的雜質、黑點、MARK、貼紙等。報告會記錄此標籤來源，結果代表對本次排除項目的辨識能力，不等同另有真實缺陷標準答案。
- 每個光源、INNER／EDGE 各自計算建議門檻。先找符合已設定限制的門檻，再最小化「OK 誤判率 + NG 漏檢率」；若校正組無可行門檻，報告會說明未達目標。
- 校正或驗收缺少 OK／NG、檔案無法讀取、跨用途存在完全相同的切片等情況，會標為資料不足，不提供可採用的建議。完全相同的正常背景也可能觸發重複檢查，請使用不同影像並重新確認資料。
- 「本次樣本符合目標」是建議門檻在此次樣本上的結果，不代表未來所有批次。請同時看樣本數與各批次結果；切片數不等同獨立 panel 數。
- 這是匯出模型的切片分數驗收，尚未包含灰塵、OMIT、遮罩等產線後處理，不代表最終整片判定。
- 使用同一前處理流程產生的切片，逐張評估並保存到磁碟；不會將全部驗收圖片加入 GPU memory bank。此功能本身不增加訓練資料可容納量。

## 留存與追溯

各子模型在 bundle 的 `validation_reports/<光源-區域>/` 保存輸入清單、標籤、批次、影像雜湊、影像副本、逐張分數與採用紀錄。資料在模型訓練前保存快照。

報告綁定模型 SHA-256 與設定指紋。模型或設定改變後，完成頁將報告標為歷史參考，不能再採用其建議。更改目前門檻不會改寫當初的校正／驗收分數。

## OOM 提醒與估算

審核頁按每個光源的 INNER／EDGE PT 分別計算正常訓練切片數，不把全部光源加總，也不把校正、驗收與 NG 算入。超過 600 張時顯示提醒，並併入原有的開始訓練確認視窗；提醒不阻止訓練。訓練日誌及子模型 metrics 也保存張數與估算。

原始特徵大小估算為「訓練張數 × 特徵網格高 × 寬 × 特徵維度 × 每元素位元組」。目前 wide_resnet50_2、512×512、layer2+layer3、FP16，每張為 64×64×1536×2 bytes；600 張約 7.03 GiB。未清理時 vstack 合併可能同時保留原始資料及合併副本，這部分約 14.06 GiB。FP32 倍增；只取 layer3 時網格及維度不同，估算會隨設定調整。

這不是總顯存峰值，也不是實測：尚有模型、batch 運算、特徵清理、coreset 與其他程序佔用；特徵清理或 datamodule 留出部分正常資料也會影響實際數量。600 張是使用者提供的經驗提醒值，以下仍可能 OOM。若要預測特定 GPU 的安全上限，需要以相同設定下成功／OOM 的實測峰值校準。若只是為了降低張數，請減少選入資料或調整設定，不要把正常切片故意排除成 NG。
