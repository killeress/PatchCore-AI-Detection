# SOP 集中發布與維護

## MOD2 配置

MOD2 預設沿用中央帳號中心位置：CAPI07，`10.174.37.81`，HTTP 80。
各機台的「幫助 / SOP」會在新分頁開啟中心；中央看板也提供相同入口
（透過系統 Web 開啟時）。不需要在各機台複製文件。

1. 將包含此功能的程式部署到 CAPI07 及需要入口的機台，重新啟動服務。
2. 在 CAPI07 的實際 Web 服務主機建立 `sop_published` 資料夾，預設位於所使用
   `server_config.yaml` 的同層。服務帳號需要讀取權限；維護人員需要寫入權限。
3. 用 WPS 編輯原始 PPTX／DOCX，原檔放在發布資料夾之外。
4. 匯出 PDF 到暫存位置，確認內容後移入發布資料夾。可建立「日常操作」、
   「異常處理」等子資料夾，系統以子資料夾作為分類、檔名作為文件名稱。
5. 開啟 `http://10.174.37.81/help/sop` 確認文件，再從另一台電腦開啟「幫助 / SOP」
   驗證閱讀與下載。

若 WPS 在 Windows，而 Web 服務跑在 Linux／容器，必須把 Windows 發布目錄
掛載到服務可讀取的位置，並將 `published_dir` 設成服務端看到的路徑。
此功能不會自動建立 SMB 分享或掛載，也不會將 Windows 路徑轉成 Linux 路徑。

## 設定

在各機台實際使用的 YAML 設定檔最上層加入（與 `web` 同層）：

```yaml
sop:
  center_url: "http://10.174.37.81"
  published_dir: "sop_published"
```

- `center_url`：中心的服務根網址，僅接受 HTTP／HTTPS，可指定埠，不含 `/help/sop`。
  留空時沿用目前中央帳號中心 IP，使用 HTTP 80。
- `published_dir`：僅在文件中心使用。可設絕對路徑；相對路徑以 YAML 所在目錄為基準。
- 修改設定後需重新啟動服務；新增或替換 PDF 不需重新啟動。
- 更新部署不含現場 SOP，不會用程式包中的文件覆蓋現場文件。

## 更新與下架

更新同一份 SOP 時，先匯出至發布資料夾以外的暫存位置，再替換同名 PDF。
避免直接匯出到正在被讀取的檔案。頁面和 PDF 不使用 HTTP 快取，使用者重新整理
或重新開啟即可取得更新。已開啟的 PDF 分頁不會自動推送更新。

需要版本標示時可把版本加入檔名。舊版另存至發布資料夾以外的備份位置；
本版不自動保存歷史。下架時將 PDF 移出發布資料夾。原始 PPTX／DOCX 不提供公開下載。
閱讀不需登入，發布權限由資料夾的檔案系統權限控制。

## MOD1 與連線確認

MOD1 未另設 `center_url` 時沿用其自己的中央帳號中心；不會自動跨網段連到 MOD2。
如果要全廠共用 CAPI07，先從 MOD1 使用者的瀏覽器驗證
`http://10.174.37.81/help/sop` 可訪問，再將 MOD1 的 `center_url` 設成該主機。
不同網段需要路由與防火牆允許使用者電腦連線到中心的服務埠。

中心關機或連線中斷時 SOP 暫時無法閱讀，本版沒有離線副本或自動同步。
資料夾不存在或無法讀取時顯示暫時無法存取；空資料夾顯示尚無文件。
