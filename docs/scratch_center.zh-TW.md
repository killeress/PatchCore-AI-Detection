# 刮痕資料集中、訓練與下發

## 操作流程

1. 各線在「推論紀錄 → 樣本歸類」選擇「表面刮痕／可救回 OK」。此分類代表可接受的表面刮痕，不是真 NG。
2. 系統依推論座標與影像方向裁出原圖 512×512 PNG，送到設定的中心。只有中心回覆儲存成功，才記錄本機歸類；中心離線時會顯示失敗，可重試。
3. 在「模型訓練 → 刮痕分類器」卡片點選「刮痕資料中心」，會前往設定的中心 `/scratch-management`；刮痕訓練頁右上方也有相同入口。由此進入原本的 `/dataset_gallery`、`/retrain`、批次驗證與下發介面，不必使用 RIC。
4. 中心整理資料後訓練新版本。刮痕正樣本仍須搭配真 NG 等負樣本；舊 RIC 資料可繼續使用。校準包含 `true_ng`、`true_black_spot`、`true_white_spot`、`misrescue_negative`。
5. 完成批次驗證後，管理員在中心選擇模型與線體，按「下發並啟用所選版本」。逐台顯示成功／失敗；部分線體失敗時，可只重試該線。

圖庫預設顯示全部批次的有效樣本，可依來源線體（IP／機台）、類別及光源篩選。未記錄來源的舊資料集中於「舊資料／未記錄來源」。需要追溯匯出批次時再展開「進階篩選」；空批次不顯示。跨批次單張及多選操作皆使用各照片原本的批次與樣本 ID，不會因同名樣本而操作到其他批次。

## 部署設定

- 中心與各線都需要更新包含此功能的程式並重啟一次；此文件不代表已更新產線。
- 中心位置沿用參數設定的「中央帳號中心位置」：MOD1 預設 `10.172.25.105`，MOD2 預設 `10.174.37.81`。
- 中心的 `central_dashboard/settings` 必須列出各線的實際 HTTP(S) API 位址並啟用。收件只接受這份清單內的來源 IP（以及中心本機）；下發只接受各線已設定的中心 IP。
- 服務須可透過設定的內網 IP 直接到達，維持實際來源 IP；經過會改寫來源的代理時，不能直接套用此 IP 信任機制。
- 中心資料目錄沿用 `server_config.dataset_export.base_dir`，未設定時為 `./datasets/over_review`。**請保留原設定及舊資料，不要改成空目錄。** 重訓頁預設使用同一目錄。
- 中心訓練及線體接收模型都需要本地 DINOv2 repo 和 `.pth`。下發只傳分類器 bundle，不重傳 DINOv2 基礎權重；缺少本地依賴會拒絕啟用。
- 模型下發需登入原有管理員帳號。中心收件使用既有內網 IP 信任模式，不把使用者密碼傳到線體。

## 儲存與相容性

中心目錄結構：

```text
over_review/
  manifest.csv                    # 如有舊版扁平資料，圖庫顯示 legacy_root
  <既有匯出批次>/manifest.csv
  manual_<來源主機UUID>/
    manifest.csv
    over_surface_scratch/<光源>/crop/manual_<UUID>_<tile_id>.png
  manifest_merged.csv
```

- 原有標籤、CSV 與 PNG 格式沿用；新資料附來源 IP、機台、機種與圖片 SHA256。來源 UUID 存於各線本機設定 DB，避免各線重複 tile ID 衝突。複製 DB 建立新線體時，需給新線獨立的 `scratch_source_node_id`。
- 收件重試使用同一個樣本 ID；中心已人工改標籤的樣本不會被相同內容重試覆蓋。
- 同時讀寫圖庫與收件使用共同 manifest 鎖，CSV 以暫存檔取代。
- 「移除目前歸類」會先通知原收件中心，把樣本標成 `removed`，排除後續訓練，保留裁圖。成功後才移除本機憑據；中心離線時維持原歸類。
- 要把已收集的刮痕改成真 NG／Pool，先移除中心刮痕歸類，再選新類別。Pool 已選入訓練或外部人工 Review 已確認的樣本沿用原有鎖定規則。
- 圖庫既有刪除功能仍會刪除檔案；中心整理標籤不會反向修改線體推論紀錄，線體顯示的是原始收集歸類。
- 真 NG、Pool 原有收集位置不變。本次新增的跨線收集入口是刮痕，沒有自動同步各線全部舊資料或誤救資料目錄。

## 下發與回滾

接收端先檢查 SHA256、載入分類器並以 CPU 試跑；失敗維持原設定。成功後使用包含內容雜湊的新檔名保存，避免同名 vN 覆蓋線體已有版本，更新 DB 與推論器設定，下次推論依新路徑載入。原檔不刪除，設定歷史保留來源及前一版路徑；可從中心再次下發舊版本回滾。

接收端 CPU 試跑不等同於產線精度驗證，也不保證 GPU 資源足夠。上線前應完成中心批次驗證，以及至少一條線的收件、訓練、下發、實際推論與回滾驗收。
