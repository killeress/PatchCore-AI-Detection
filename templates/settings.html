💡 B0F 亮點偵測 — 參數說明

B0F00000(黑畫面) 圖片使用局部對比偵測取代 PatchCore。
偵測邏輯：median filter 估計背景 → 計算局部差異 → 差異超過閾值且面積 ≥ min_area 判定為亮點。
diff_threshold 局部對比差異閾值（越低越敏感）
median_kernel 背景估計觀察範圍（必須為奇數，最小 3）
min_area 亮點最小連通面積（低於此面積視為雜訊忽略）
threshold 絕對亮度上限（超過直接判定 NG）
⚠️ median_kernel 設定注意
此參數決定背景估計的「觀察範圍」— 系統用多大的區域來判斷什麼是正常背景、什麼是異常亮點。
✗ 值太小（1~5）
觀察範圍太小，會把缺陷本身當成背景，導致缺陷「消失」而漏偵

🎯 兩階段精準比對 — 參數說明

舊版 COV 判定為「灰塵」時，啟動二次確認。
用 heatmap 框出大概的問題區域 → 回到原圖在該區域內找實際特徵點 → 逐點比對 dust_mask 判定灰塵或真實缺陷。
流程示意
Step 1: Heatmap top 5% → 框出「熱區」(大概位置)
Step 2: 在熱區範圍的原圖中找「跟周圍不一樣的點」
       → 計算每個 pixel 跟局部背景(Gaussian Blur)的差異
       → 差異排在前 X% 的 pixel 被標記為特徵
Step 3: 每個特徵點比對 dust_mask (ext=0, 不膨脹)
       → 重疊比例 ≥ 閾值 → 灰塵
       → 重疊比例 < 閾值 → 真實缺陷 → NG
dust_ratio (0.3) 特徵點被灰塵蓋住多少比例才算灰塵？
例: 特徵佔 10 pixel，其中 8 pixel 在 dust_mask 內 → 80% ≥ 0.3 → 灰塵
↑ 調高 (0.8): 要幾乎完全蓋住才判灰塵 → 過殺增加
↓ 調低 (0.1): 沾到一點灰塵就判灰塵 → 漏放增加
bg_blur (31) 看多大範圍算「局部背景」？
31 = 用 31×31 pixel 的 Gaussian Blur 估計背景亮度，跟背景差異大的就是特徵
↑ 調大 (51): 背景更平滑，適合均勻面板，但大缺陷可能被平滑掉
↓ 調小 (15): 背景更局部，能抓小變化，但紋理容易產生假特徵
diff_percentile (90) 差異排在前幾 % 才算特徵？
90 = 只有差異最大的前 10% pixel 才被標記為特徵點
↑ 調高 (95): 只抓最明顯的前 5% → 微弱缺陷可能漏掉
↓ 調低 (80): 前 20% 都算 → 抓更多但容易把正常紋理也抓進來
min_area (3) 特徵至少要多大才算數？
3 = 至少 3 個 pixel 連在一起才算一個特徵，低於此視為雜訊
↑ 調大 (10): 只認大特徵 → 小缺陷被忽略
↓ 調小 (1): 1 pixel 也算 → 雜訊容易被當成缺陷
fallback_score (0.7) 安全網: 找不到特徵時怎麼辦？
如果原圖影像處理找不到任何特徵，但 PatchCore 分數 ≥ 此值 → 保守判 NG
↑ 調高 (0.9): 只有極高分才觸發安全網 → 安全網很少啟動
↓ 調低 (0.5): 中等分數就觸發 → 兩階段幾乎不會判 OK
為什麼需要兩階段？
PatchCore 模型的 heatmap 有「擴散」特性 — 一個小黑點會在 heatmap 上產生大面積紅色區域 (receptive field ~60px)。 灰塵的 dust_mask 只標記灰塵實際位置，比 heatmap 擴散區域小很多，導致舊版 COV 比對尺度不匹配。
兩階段繞過這個問題：不在 heatmap 上做灰塵分離，改在原圖 pixel 層級直接比對，灰塵和缺陷都是精準位置，不存在擴散問題。

💡 指標差異說明：
• Coverage (預設): 交集 / 灰塵面積
只需判斷熱區是否蓋住灰塵，不受熱區面積過大影響。推薦用於灰塵情境。
• IoU: 交集 / (灰塵 + 熱區)
標準重疊指標。若熱區範圍過大，分數會被稀釋變低，可能導致漏檢。
