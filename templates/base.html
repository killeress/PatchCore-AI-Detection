{{ station_name }} 檢測系統現行邏輯與流程

Current Detection Pipeline & Decision Flow

以下以目前的 inner／edge 新架構為主；實際啟用的前處理、推論模式、門檻與後濾條件，仍以目前機種的模型設定及參數頁為準。舊式模型設定才可能使用傳統 CV 邊緣檢測。
1. 請求與預檢
2. 定位與切塊
3. AI 推論
4. 交叉驗證
5. 多層後濾
6. 判定與回報

01 請求、定位與切塊

  • > 依 AOI 請求中的 ModelID 選擇機種及目前啟用的模型 bundle，並整理最新一組點燈影像。
  • > 優先使用 W0F 畫面，透過 Otsu＋四角 Polygon 找出產品邊界，並讓其他點燈畫面共用定位結果。
  • > 依設定走完整 Grid 或 AOI 座標中心切塊；512×512 Tile 會分為 inner／edge，靠邊 Tile 會向產品內側修正。

02 PatchCore 與 AOI 推論

  • > 五種主要點燈各自使用 inner／edge PatchCore 模型與門檻，產生異常分數及熱圖。
  • > Polygon、MARK 與不檢測區遮罩會先作用於熱圖及分數，再與該 lighting／zone 的門檻比較。
  • > AOI 座標 Tile 未達門檻時只做 Track-only；B0F 黑畫面使用亮點偵測，不走 PatchCore。

03 MARK、不檢測區與最終判定

  • 1. 從 W0F 畫面辨識 點陣 MARK 字元，保留文字、信心值、方向與位置資訊。
  • 2. Polygon 外部、MARK 與人工設定的不檢測區會遮罩或降低熱圖權重；相關結果仍保留供追溯。
  • 3. 炸彈模擬缺陷、不檢測區與 Track-only 不列入一般 NG；啟用時，Scratch Classifier 會再過濾高信心表面刮痕。
  • 4. 彙總後仍有有效缺陷即為 NG，否則為 OK；原始 NG 整片符合規格內條件時轉為 OK-i。QJPG 對外回覆為 OK，系統內仍保留 OK-i 追溯紀錄。

04 OMIT／PINIGBI 表面污染交叉驗證

PatchCore 出現達門檻的異常，且 OMIT／PINIGBI 影像可用時，系統才會以對應位置的污染遮罩逐熱區複驗；實際指標與選配功能依目前參數設定。
  • 1.
    建立污染遮罩：CLAHE、Top-Hat、Otsu 與連通區域分析會提取亮／暗顆粒、細長刮痕，以及設定啟用時的氣泡或像素格抑制結果。
  • 2.
    逐熱區比對：將熱圖前段高分區拆成獨立連通區域，再依設定使用 Coverage 或 IoU 與污染遮罩比對，並檢查峰值、次峰及高覆蓋率條件。
  • 3.
    保留真實缺陷：所有熱區皆符合污染條件才標記為 DUST；只要仍有非污染熱區就保留為 REAL_NG。OMIT 缺圖或過曝時不會據此濾除 NG。
// 判定數據標籤釋義
P / S / Bub: 顆粒／刮痕／氣泡  |  COV / IOU: 目前設定的重疊指標  |  REAL_NG: 仍存在非污染熱區
// 常見結果標記
OK 無有效缺陷 NG 真實缺陷 OK-i 規格內轉 OK DUST 表面污染濾除 EXCLUDED 不檢測區 BOMB 模擬缺陷 TRACK-ONLY 未達 NG 門檻
